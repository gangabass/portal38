# Portal38 — запись для семьи

PWA для 2–3 семейных аккаунтов портала https://portal38.is-mis.ru/.
Frontend — статический Vite/JavaScript для GitHub Pages `/portal38/`, backend — Node.js 24, SQLite и Web Push в отдельном Docker-контейнере рядом с Dnevnik.

## Что реализовано

- Вход на портал по логину/паролю с серверной сессией и повторной авторизацией.
- Выбор человека из картотеки, специальности, поликлиники (включая другие медорганизации), одного/нескольких врачей либо любого врача выбранной поликлиники.
- Талоны «до 1 года» распознаются по заголовку, подсказке и примечанию дня. Для старших детей и при неизвестном возрасте они исключаются; возраст берётся из картотеки без угадывания даты рождения.
- Диапазон дат, дни недели и интервал времени в `Asia/Irkutsk`.
- Проверка активных правил каждые 60 секунд; запросы одного аккаунта выполняются последовательно. Длинный проход не запускается повторно параллельно; фактическое время проверки видно у правила.
- Ручной режим показывает все подходящие слоты. Новые слоты вызывают push; повторные проверки того же слота не вызывают новых уведомлений.
- Автоматический режим выбирает ближайший по времени слот среди выбранных врачей.
- До создания правила и непосредственно перед записью проверяются текущие записи человека. Ограничение по специальности действует и при выборе другого конкретного врача.
- Состояние `booking` сохраняется непосредственно перед отправкой запроса записи, после проверки талона. Сбои до отправки сохраняют этап и причину и не считаются неопределённым бронированием. Неоднозначный результат или перезапуск во время попытки переводят правило в `needs_review`. Повторная автоматическая попытка и другие правила на ту же специальность блокируются до проверки человеком.
- Данные аккаунтов, cookies, правила и push-подписки зашифрованы AES-256-GCM в SQLite. Семейный ключ приложения отделён от паролей портала. Внутри приложения члены семьи имеют общий доступ к подключённым аккаунтам и правилам.
- Диалог «Записи»: все текущие записи выбранного человека, врач, поликлиника и время. Отмена требует подтверждения; сервер заново проверяет принадлежность записи и CSRF-токен, затем проверяет исчезновение записи из активных. Связанные отслеживания ставятся на паузу и сами не возобновляются. Если портал запрещает отмену, доступна ссылка на картотеку.
- PWA, offline-оболочка, Web Push. Ответы API и персональные данные не кешируются в браузере. Ключ приложения хранится в sessionStorage; после нового запуска может потребоваться повторный вход. Уже настроенные push продолжают работать.

## Локальный запуск

Нужен Node.js 24.

```powershell
npm ci
npm run keys
npm start
```

Генератор дополняет `server/.env`, сохраняя существующие непустые значения и тестовые credentials. Откройте файл локально: скопируйте `FAMILY_ACCESS_KEY` для входа в приложение. Секреты не выводятся в терминал. `VAPID_SUBJECT` замените своим email в формате `mailto:...`.

В другом терминале:

```powershell
npm run dev
```

Откройте http://localhost:5173/portal38/, API — http://localhost:3002. Введите семейный ключ, добавьте аккаунт портала и выберите человека. Тестовые `PORTAL_TEST_LOGIN`/`PORTAL_TEST_PASSWORD` не импортируются в приложение автоматически.

Для production-preview с service worker:

```powershell
npm run build
npm exec vite preview -- --host 127.0.0.1 --port 5173
```

PWA/push проверяются на HTTPS-размещении либо на localhost. В dev-режиме service worker отключён.

## Проверки

```powershell
npm test
npm run build
```

Тесты покрывают фильтрацию и часовой пояс, выбор первого талона, конфликты по специальности, ручной/автоматический режим, неизвестный результат, восстановление после перезапуска, шифрование, разбор HTML, CORS и авторизацию API.

Проведена проверка реального чтения под временным аккаунтом: вход, 5 человек в картотеке, список специальностей и поиск врачей в других медорганизациях. Автозапись проверена на существующем пользовательском правиле без изменения его условий; созданная запись дополнительно подтверждена в картотеке портала. Обнаруженное ограничение «только дети до года» учитывается до выбора талона.

### Что ещё требует живой проверки

1. Успех бронирования проверяется по точному совпадению человека, врача и времени приёма в картотеке. Идентификатор созданной записи отличается от идентификатора талона; русские даты портала разбираются отдельно. После отправки выполняются до трёх проверок картотеки без повторного бронирования. Если результат неизвестен — `needs_review`, сведения об этапе сохраняются в `lastBookingAttempt`. Кнопка «Проверить и продолжить» заново читает картотеку: при найденной записи останавливает правило, при конфликте не возобновляет, при отсутствии записи позволяет продолжить по прежним условиям после двухминутного защитного интервала.
2. Текущие записи разбираются по отдельным карточкам. При нераспознанной специальности новая запись консервативно блокируется. Реальная отмена записи при разработке не выполнялась: схема запроса изучена по JavaScript портала, а отправка, CSRF, проверка результата и пауза правил проверены на подменённых ответах. История используется только для исследования формата; диалог загружает текущие записи.
3. Сейчас отслеживаются только бесплатные очные талоны стандартного типа `1`. Платные приёмы, телемедицина и другие типы исключены.
4. Календарь используется в пределах доступного на портале горизонта. Направления, дополнительные требования клиники и специальные сценарии записи требуют отдельной проверки.
5. Визуальная проверка браузером и доставка push на реальных Android/iPhone в текущей среде не выполнены.

Перед включением автозаписи проверьте один нужный талон вручную в приложении. При `needs_review` сначала проверьте «Мою картотеку» на портале. После выяснения результата удалите старое правило; новое создавайте только при отсутствии уже оформленной записи.

## Размещение

См. [server/README.md](server/README.md). Публикация frontend запускается вручную workflow `Deploy PWA to GitHub Pages` после настройки API. Исходники не содержат адресов с паролями или серверных секретов. `.env`, данные и приватные файлы исключены из Git и Docker build context.

## Структура

- `src/` — интерфейс и Web Push client.
- `public/` — manifest, service worker, иконки.
- `server/portal.mjs`, `adapter.mjs`, `parsers.mjs` — работа с порталом.
- `server/domain.mjs` — фильтры, конфликты и выполнение правила.
- `server/index.mjs` — API, очередь push и минутный цикл.
- `server/store.mjs` — зашифрованная SQLite.
- `tests/` — проверки без реального бронирования.

Сайт портала не предоставляет здесь документированный API: его HTML и поведение могут меняться. При неизвестном формате приложение останавливает действие и сообщает об ошибке.
